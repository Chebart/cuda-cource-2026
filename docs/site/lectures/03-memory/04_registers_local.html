Зачем разворачиваем внутренние циклы

Строка 17: у потока 64 числа. В строке 19 просим компилятор развернуть цикл. Вместо values[i] получаем values[0], values[1] и так далее. Так компилятор знает индекс заранее и может выбрать регистр для каждого числа.

Строка 27: прибавляем 1; на следующем шаге снова нужны все эти числа. Разворачиваем три коротких цикла — загрузку, прибавление и запись. Цикл по шагам оставляем. Делаем это в обеих сборках: для сравнения меняем только лимит регистров.

Запуск: что меняет лимит регистров

nvcc -std=c++17 -O3 -arch=sm_75 -Xptxas=-v 04_registers_local.cu -o registers
./registers

nvcc -std=c++17 -O3 -arch=sm_75 -Xptxas=-v --maxrregcount=32 04_registers_local.cu -o registers_capped
./registers_capped

В обеих сборках добавляем -Xptxas=-v, чтобы увидеть отчёт компилятора. Во второй задаём лимит флагом --maxrregcount=32. На Quadro RTX 6000 с CUDA 13.1 отчёт вышел таким:

Без лимита: 72 регистра; 0 spill stores, 0 spill loads
С лимитом: 32 регистра; 976 Б spill stores, 1012 Б spill loads

Сначала посмотри на spill stores и spill loads: с лимитом там уже не нули. Компилятор добавил запись части чисел в локальную память и чтение обратно. Эти числа он печатает при сборке, ещё до запуска ядра.

Теперь запускаем обе версии. В начале массива получаем [128, 129, 130, 131]: к [0, 1, 2, 3] прибавили 128. Программа проверяет все 524 288 чисел. Теперь сравни среднее время запуска: 15,82 мкс без лимита и 186,58 мкс с лимитом по CUDA Events. После прогрева замеряем 100 запусков; ответ копируем и проверяем уже после замера.

Дополнительно: что будет без разворачивания циклов

Мы посмотрели машинный код: с лимитом появились инструкции чтения и записи local memory, без лимита их не было.

А если убрать #pragma unroll? В CUDA 13.1 без лимита мы убрали все три директивы. Компилятор всё равно обошёлся без local memory. Затем явно запретили разворачивать эти циклы. В отчёте видим 256 байт стека, а в spill stores и spill loads стоят нули. Индекс i меняется во время выполнения цикла, и компилятор в этой сборке сразу положил массив в локальную память.
