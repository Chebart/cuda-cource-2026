Константная память: один адрес на warp или 32?

Каждый поток складывает числа от 1 до 32 из одной таблицы. Сумма должна быть 528 в обеих версиях. Меняем только порядок чтения: либо на каждом шаге весь warp читает одну ячейку, либо каждый поток читает свою. Сравним время.

Те же числа, разный порядок чтения

До запуска копируем таблицу с CPU в constant memory. Без сдвига все потоки начинают с table[0]. Со сдвигом поток 0 начинает с table[0], поток 1 — с table[1] и так далее. Дойдя до конца, продолжаем с начала, пока не прочитаем все 32 числа.

Почему нет гонки: таблицу заполняем до запуска. В ядре её только читаем, а сумму каждый поток пишет в свою ячейку output[tid]. Запуски идут друг за другом в одной очереди. Разные адреса влияют на время, но не портят ответ.

Как выбираем первую ячейку

Строка 6: заводим таблицу __constant__. До запуска скопируем в неё числа с CPU.

Строка 17: без сдвига начинаем с ячейки 0, со сдвигом — с ячейки с номером потока внутри warp (lane).

Строка 22: после ячейки 31 возвращаемся к ячейке 0 с помощью % 32. Так каждый складывает все 32 числа.

Запуск: общий адрес против 32 разных

nvcc -std=c++17 -O3 -arch=sm_75 07_constant.cu -o 07_constant
./07_constant

Вот вывод на Quadro RTX 6000:

One address: sum = 528; 3.69 us/launch; PASS
Different addresses: sum = 528; 26.07 us/launch; PASS

Сверь sum в обеих строках: везде 528. Порядок чтения разный, но складываем те же числа. Печатаем сумму первого потока. PASS получаем, если все 32 768 потоков дали 528.

Теперь сравни us/launch: 3,69 мкс с общим адресом и 26,07 мкс с разными. В первом случае warp на каждом шаге получает одно число на всех, во втором ему нужны 32 ячейки.
