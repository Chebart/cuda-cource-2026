Копируем массив с GPU на CPU: когда можно читать?

На GPU лежит массив [2, 4, 6, 8]. Хотим забрать его на CPU. Ставим копирование в очередь и не ждём сразу: разберём, в какой момент числа можно прочитать.

От запуска копирования до чтения массива

Сначала копируем массив на GPU и ждём, пока он туда попадёт. Затем создаём очередь (stream). В неё ставим только копирование обратно: с GPU в RAM.

  1. 1. Просим скопировать

    CPU
    Просит скопировать массив с GPU в RAM.
    CUDA
    Выполняет копию из очереди.

  2. 2. Не ждём сразу

    CPU
    Может работать с другими данными.
    CUDA
    Массив ещё может копироваться.

  3. 3. Читаем результат

    CPU
    Ждёт конца копирования, затем читает результат.
    CUDA
    Массив уже в RAM.

Если вызвать cudaMemcpy для копии с GPU на CPU, вызов сам дождётся результата. Здесь берём cudaMemcpyAsync с закреплённым буфером: решаем сами, когда подождать.

Что выигрываем
Пока массив копируется, CPU может, например, подготовить следующий массив в другом буфере.
Где ждать
Ждём до того, как читать результат или освобождать буфер, в который копируем.

Листинг 02

Пул памяти GPU: что остаётся после возврата буфера?

Дважды берём у пула буфер на 1 МиБ и возвращаем его. Хотим увидеть, останется ли свободная память у пула и хватит ли её на второй запрос.

Буфер вернули, а пул может оставить память

used — сколько памяти сейчас занимают выданные буферы. reserved — сколько памяти держит пул целиком: и выданной, и свободной.

Что выигрываем
Когда нужен новый буфер, пул может взять память из резерва и не запрашивать её заново.
Чем платим
Свободный резерв по-прежнему занимает память GPU.

Сначала print_pool_usage печатает оба числа до первого запроса. С ними сравниваем показания после выделения и возврата.

Запуск: хватило ли резерва на второй буфер?

Нужны CUDA Toolkit 11.2+ и GPU с поддержкой пулов памяти.

nvcc -std=c++17 -O3 -arch=sm_75 02_pool.cu -o pool
./pool

Пример вывода на Quadro RTX 6000:

before first alloc: used=0 B, reserved=0 B
Pass 1
after alloc: used=1048576 B, reserved=33554432 B
after free: used=0 B, reserved=33554432 B
Pass 2
after alloc: used=1048576 B, reserved=33554432 B
after free: used=0 B, reserved=33554432 B

Сначала посмотри на before first alloc: порог уже задали, а оба счётчика по нулям. В первом after alloc буфер занял 1 МиБ (used), а пул зарезервировал 32 МиБ (reserved). В первом after free снова used=0: буфер вернули, а reserved остался 32 МиБ.

Теперь сравни reserved в двух строках after alloc: оба раза 32 МиБ. Пулу хватило резерва на второй буфер.
