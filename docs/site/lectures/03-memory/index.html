CUDA / Лекция 03

Память в CUDA: девять примеров

Как передать массив между CPU и GPU? Зачем иначе размещать числа, если результат тот же? Разберём на коротких программах.

Сначала посмотри на схему, потом прочитай пояснения рядом с кодом. Скачай .cu и выполни команды из раздела «Запуск» в папке с этим файлом. Под командами — что искать в выводе.

  1. 01 · Копируем массив с GPU на CPU: когда можно читать?

    Ставим копию в очередь и сразу идём дальше. Разбираем, где нужно подождать, чтобы прочитать все числа.

  2. 02 · Пул памяти GPU: что остаётся после возврата буфера?

    Дважды берём по 1 МиБ. Смотрим, нужна ли пулу новая память при втором запросе.

  3. 03 · Один массив для CPU и GPU

    Через Unified Memory прибавляем 1 на GPU и читаем тот же массив на CPU без вызова cudaMemcpy.

  4. 04 · Что происходит, когда не хватает регистров?

    Ограничиваем число регистров при сборке. Смотрим, понадобилась ли локальная память и как меняется время.

  5. 05 · Удваиваем x: массив векторов или отдельный массив?

    Сравниваем AoS и SoA: какие адреса читают потоки и почему одно ядро работает быстрее другого.

  6. 06 · Конфликт банков: зачем добавлять пустой столбец?

    Читаем первый столбец из shared memory. Числа те же, а при ширине 33 вместо 32 работают разные банки.

  7. 07 · Константная память: один адрес на warp или 32?

    Каждый поток считает ту же сумму. Сравниваем время, когда потоки читают одну ячейку за шаг и когда читают разные.

  8. 08 · Texture: читаем между четырьмя пикселями

    Ставим точку в центр массива 2×2 и получаем число, которого нет ни в одной ячейке.

  9. 09 · Surface: заполняем CUDA-массив четырьмя потоками

    Каждый поток пишет одно число. Разбираем, почему X указываем в байтах, а Y — в строках.

Сборка и запуск на кластере

Мы собрали и запустили все девять примеров на кластере «Громозека»: CUDA Toolkit 13.1, видеокарта NVIDIA Quadro RTX 6000. В командах -arch=sm_75 — архитектура этой карты. Если архитектура твоей видеокарты другая, подставь её в -arch.

Дополнительно: проверка памяти и профилирование

Эти инструменты разберём в следующих лекциях. Для первого запуска они не нужны.

Хочешь проверить обращения к памяти? Собери transfer по команде на странице примера и запусти:

compute-sanitizer --tool memcheck \
  --error-exitcode 99 ./transfer

После массива посмотри на строку ERROR SUMMARY: там видно, нашёл ли memcheck ошибки при обращении к памяти.
